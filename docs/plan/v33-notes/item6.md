## CHANGELOG.md (beta.33, Added)

- **A budget, said before it is spent (ADR 0210 part 5).** Every run that calls a model, in any mode but replay (model, headless Claude Code, copilot-acp, hand-off; a Copilot session the step runner opens, a task run, a live eval), says first on standard error what it plans: `Budget: The read of forge-orders plans 3 sessions and about 36,400 tokens; limits: 40 sessions a day (12 used), 2,000,000 tokens a month (310,000 used).` One command's runs share one plan: the read plans each batch left as a session with its files and instructions, `map --all` the whole estate's parts once, and any other run one session of its first prompt; once a command spends past its plan, each further request checks the run, day and month again. A run whose result is written (a read) first checks that it can be: no other write holds the metarepo's lock, and no upgrade is owed (the build's `not-upgraded`). Past `budgets.limits` it asks at a terminal (`[y/N]`); unattended (CI, no terminal, an assistant's session, the app) it stops before its first request with exit 2, unless given `--yes`. Each person's use is counted on their machine, one line a request (a cancelled one too, with its prompt's tokens), by UTC day and month, in `.runs/.usage/<user>.jsonl` (never in the catalog; the name safe on Windows; pruned with the runs to this month and the last); with no limit set, a count that can't be written never fails a run. The limits are soft under runs at the same time. VS Code never takes the budget line for why a step stopped. `atticus doctor` gains an AI budget check (the limits and what is used; a warning once one is used up). In the app, the plan line is the run panel's start line (the job's progress), and the AI tab of Set up shows the limits and keeps them when it saves. The read already sent its files in as few sessions as the model's limit allows (next-fit at the limit's room; a larger limit cuts them): unchanged, now tested.
