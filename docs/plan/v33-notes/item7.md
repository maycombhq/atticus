# v33 notes: item 7, recipe first and the readers off by default (ADR 0210 parts 2 and 6)

What the shared files should say for the `b33/item7-recipe-first` branch. The integrator copies these in; this builder did not edit `CHANGELOG.md`, `docs/build-status.md` or `docs/codebase-map.md`.

## CHANGELOG.md (beta.33, Added)

- **Recipe first, model on request (ADR 0210 part 2).** An active reading rule with an `extract` (a recipe, proven on two repos) now holds for every repo of its type, not only the repos its proof names. A read of a repo whose type has active recipes runs them first, with no model: their facts are merged into the facts on file and go through the same verifier as a batch's (a fact it refuses is in `<repo>.rejected.jsonl`, as a model's is), and are written per commit as reads are. The files the recipes read are never sent to the model: the model's batches, its read plan and its parts (`map --estimate`, `map --all`, copilot-acp) are planned over the rest only, so item 6's budget line counts only the model's part. The read's first lines say who reads what: `Read by recipe 3 files, by the model 0 files.`, then `By recipe: 9 facts kept, 0 rejected by the verifier.` and each line a recipe matched that wrote no fact (`dropped`), with why. A repo the recipes read whole sends no prompt; with AI off (no runtime, or runtime.yaml refuses one) the recipes still read and the model's files are said to wait. `map --all` reads each repo's recipes before its sessions, and lists a repo they read whole as `read by its recipes alone (N files): nothing for the model`. `map --estimate` says the split (and `recipe.files` in `--json`). `atticus rules <repo>` marks a rule's recipe, its proof's repos, or that it is not proven.
- **What a recipe reads, and when it holds (review of item 7).** A recipe names its files (schema). A file is the recipes' only when they wrote a fact from it and every fact the last read wrote there is of a kind they write; any other file a recipe names goes to the model whole, and nothing a recipe found there is written. A file the recipes read keeps only their facts (a model's earlier entry on the same line is replaced), and every fact a recipe wrote before (any key, a renamed one too) is replaced by this read's. A proof carries the digest of the recipe's `extract` and `files`: a recipe edited since is a draft, saying so; a proof on a repo of another type proves nothing; and only `reading-rules/types/<type>.yaml` holds a recipe for its type. `map --all` stops on a facts file it can't read and ends with 1 when the verifier refused a recipe's fact. In the app, Map › Decided by AI lists each type's recipes, proven (on which repos) or a draft and why (`GET /api/reading-rules/recipes`, C4 3.21.0), and Set up › AI says whether the readers run (`readers` on `GET /api/settings/ai`).
- **The deterministic readers off by default (ADR 0210 part 6).** A scan runs the built-in readers and dialects only where the org pack's `conventions.yaml` says `readers: "on"`; off, a repo is projected from its verified facts alone and its slot says `readers-off`. The verifier's own use (verify's OpenAPI reader for skipped operations) is unchanged. `atticus frameworks`, `dialect` and `onboard` say on standard error that the readers are off and how to turn them on. Nothing is deleted. **An existing team keeps them:** `atticus upgrade`'s step `readers-kept-on` writes `readers: "on"` into conventions.yaml (at schemaVersion 3) where the catalog has slots the readers wrote, and says to set `readers: "off"` to read with recipes and the model only; a new pack gets them off. A scan with the readers off builds from the facts; with no facts to build from it is no failure (exit 0, the app and CI too) and says to read with `atticus map --all`; it no longer advises drafting a dialect.

- C6: reading rules schema 3 (unreleased, so no new number): a rule with an `extract` names its `files`; `learned.proof.digest` (16 hex, `recipeDigest` of the extract and files), required on an active recipe's proof and written by `proveRecipe`.
- C4 3.21.0, additive: `GET /api/reading-rules/recipes` (`ReadingRecipesView`); `readers` on `GET /api/settings/ai`. `docs/api/openapi.json` regenerated.
- C6: conventions.yaml schema version 3: `readers`, optional, `on` or `off` (off when absent). A version 1 or 2 file reads as it did (as 2); a file at 1 or 2 that sets `readers` is refused with "readers needs schemaVersion 3", and `atticus upgrade`'s new step `conventions-v3` (`migrateConventionsV3Text`) writes the number only. A note's write (`repo-type note --org-wide`) keeps a file at 2 (beta.32 reads it) and never lowers a 3. beta.32 refuses a version 3 file whole. `docs/spec/contracts/c6-org-pack.md` regenerated. The facts file is unchanged: a recipe's fact is `by: "reader"` with an id `<kind>.<rule key>.<hash>`, the provenance it already had (no field was added; the facts file has no field naming the rule, so the id is how a fact is traced to its recipe).

## Open, for the next step

- **"Model on request" is the narrow reading.** With a runtime, the files no recipe reads still go to the model in the same read (the task asked for that); the ADR's "the model reads a repo when a person asks, or when the join's misses name it" for the recipe's own files is not wired, nor the model writing or correcting the recipe at the end of a read.
- **The app.** The split and the recipes' lines reach the app as the read job's lines; Connect's rule from a pairing never makes a recipe, so it shows none. A scan with nothing to build says the next step under its sources table.
- **The suites run with the readers off**, but for these, whose tests are about what the readers read: `fixtures/forge` (the M1 scan, the slots, the golden build), `messy` (the phase 2 readers gate), `gateways` (gateway dialects), `scan-settings` (scan settings steer the readers), `scan-verify` and `verify/test/fixtures/metarepo` (a scan beside the facts: the readers' slot), `scanner-plugins` (plugins run after the readers), `estate` (`hosts-asked-cli`: the questions the readers' calls raise), `forge-field` (generated by `cli/test/field-estate.ts`: an estate the readers scanned before beta.33, as an existing user's is kept), and the packs built in `adopted-root-cli`, `setup-cli` and `onboard-framework-cli` (a repo with no facts scanned by the readers; the framework models' advice), `scanner/test/m1-exit` (it times the readers). `cli/test/golden/big-estate.json`'s build.json digests were rewritten (no readers steer its slots now).
- A Copilot session (paste or copilot-acp) writes its facts to the facts file itself; the recipes' facts are already there, verified, and the next verify checks them again.
