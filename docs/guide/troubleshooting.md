# Troubleshooting

Start with `atticus doctor` in the metarepo: most problems are on the machine, and each line it prints says what to do. It also says how AI steps run here (handed off to your assistant, or model mode with which provider and whether its key variable is set, by name only) and whether the `/atticus-*` slash-command files are there and current. It makes no network call, so it doesn't call the model.

## Where to see what Atticus is doing

Open the **Console** at the foot of the app (in the bottom panel, under the page; in the classic layout **Open the Console**; it is there on every page, in a browser and in the VS Code and IntelliJ panels). It lists everything Atticus is doing or did lately on this metarepo, newest first, wherever it was started:

- what you started in the app: a scan, a sync, Apply, Propose, Bring in, an AI step, the critic, a wiki's sync, a team's tool, a run's Done, a Copilot run (with its tab per session);
- the long commands run in a terminal, by VS Code or IntelliJ, or by a Copilot session: `atticus map` (and `map --all`), `verify`, `scan`, `workspace sync`, `task run`, `task run-ready`, `knowledge scan`, `upgrade`, `handoff done`, `index rebuild`, `reconcile`;
- the hand-off runs that wait for your assistant, with where the prompt is and how to finish it, and what Done printed once it ran.

Each entry says what it is, where it was started, whether it is running, done, failed, cancelled, waiting or "ended without saying" (its terminal was closed, or it crashed), and when. Pick one to see what it printed, live: follow the end, search, copy. While anything runs, a strip under the top bar says what and how far, with **Show in the Console** and **Stop** for what the app started. A command run in a terminal stops in its terminal (Ctrl+C).

A job the app started (a scan, a sync, an AI step, Apply) is kept the same way, so it is still in the Console after the app restarts, titled by what it is and the repos, changes or runs it names (never words you typed). One still running when the app closed says "stopped when the app closed"; one another `atticus ui` window runs says to stop it there. `atticus ui` in a folder that isn't a metarepo keeps nothing there.

A command run outside the app keeps what it prints in `.atticus/logs/runs/<run>.log`, and a small record of itself (the command words, the repo, change and run ids it was given, its flag names, and in its title the values that are ids, names or dates, never one that looks secret; when it started and how it ended) in `.atticus/logs/running/<run>.json`. Each line is redacted as the log is (below). Only the last 50 runs are kept, each log to its last 2 MB or so. Quick commands (help, list, show, `next`, `--json` questions, `--check`, `--dry-run`) keep nothing. `ATTICUS_RUN_LOG=off` turns it off for a command, and for the app's jobs when `atticus ui` is started with it. The last 50 runs are counted together, the terminal's and the app's. `.atticus/logs/` is never committed.

## The log

`.atticus/logs/atticus.log` in the metarepo: one JSON object per line, newest last. Each command with its flag names, exit code and time; failed API calls; crashes with their stack. Secrets, tokens, credentials in URLs, your home folder and user name are hidden before anything is written. `ATTICUS_LOG=debug atticus <command>` records more for one run.

## Asking for help

```bash
atticus support bundle
```

writes `.atticus/logs/atticus-support-<time>.zip` (or `--out <file>`): versions, operating system, the machine checks, the setup checklist, org-pack problems, counts of records, changes, repos and inputs (never their names) and the last 2,000 lines of the redacted log. Nothing is sent anywhere. Read every file before it leaves your organisation: an error message can still name one of your systems or changes, so remove what you can't share.
