# M3 exit report

Run on 2026-10-18 on the cloud build machine, from `main` through ADR 0040, with the suite in `packages/m3-exit` (`@maycombhq/m3-exit`, private, tests only).

The suite drives Atticus the way a team would, through the CLI's `main()` (the built `@maycombhq/cli`), in a temp copy of `fixtures/forge` with the `fixtures/forge-change` and `fixtures/forge-speckit` org-pack additions laid over it. The seven Forge repos are committed and served from local bare remotes, `atticus workspace sync` clones them, and `atticus scan` builds the catalog. Outside systems (Git host, work tracker, service desk) are the C4 mocks `runtime.yaml` names; AI runs as recorded replay from hand-written recordings (`fixtures/forge-change/recordings/` and `packages/m3-exit/test/fixtures/recordings/`); builds use a fake build runner (a Node script set as the repos' build command). Nothing touches the network.

Run it with `pnpm --filter @maycombhq/m3-exit test` (about two minutes). Tests named `GAP …` assert what the exit needs where the product falls short today and are expected to fail (`it.fails`); run with `M3_EXIT_SHOW_GAPS=1` to see why each fails. When a gap is fixed its test starts to "unexpectedly pass": change `gap(` to `it(`.

Result today: **45 passed, 8 expected failures (product gaps), 53 tests.**

## Product gaps found (each has a `GAP …` test)

1. **`critic-ai-wiring`** (blocks the critic exit from the CLI). `packages/cli/src/main.ts`, the `critic` branch, calls `critic()` with no deps, and `packages/cli/src/critic-commands.ts` `critic()` only takes a runtime through `CriticDeps.runtime`; there is no `--mode` and no `runtimeForCli()` call. From the command line layer 2 never runs ("no AI runtime was given; layer 1 ran alone"), so the AI-only seeded problems (b13 concurrency, b14 story without spec, g12 default limit, g13 vendor failure behaviour) are missed. Fix: build the runtime with `runtimeForCli(root, { mode })` as `plan stories` does. Test: `critic-seeded.test.ts`.
2. **`task-run-replay`**. `packages/taskrun/src/run.ts` `runTask()` creates the runtime with `createRuntime(...)` without `replayDir`, and `packages/cli/src/run-commands.ts` `taskRun()` doesn't map `ATTICUS_REPLAY_DIR` into `runtimeOptions`. `atticus task run … --mode replay` answers "Replay mode needs a folder of recordings (ATTICUS_REPLAY_DIR)." even when it is set. Workaround in the suite: the exported `taskRun()` with `runtimeOptions.replayDir`. Test: `lifecycle.test.ts`.
3. **`finding-gate`**. A knowledge gap asked at the design gate is raised again, open, at the plan gate with the same id. `packages/naysayer/src/act.ts` `act()` searches gates in `reviewedGates()` order and finds the design one ("already asked"); `ActOptions.gate` exists but `packages/cli/src/critic-commands.ts` `findingAction()` never passes it and `main.ts` has no `--gate` for `finding`. The plan gate's gaps can't be acted on from the CLI. Workaround: `act(..., { gate: "plan" })`. Related observation: asked/dismissed states carry across rounds of one gate, not across gates, so every gate re-asks the same owner questions. Test: `lifecycle.test.ts`.
4. **`trace-gate-lifecycle`**. ADR 0039 says the built-in `trace` gate is "read by the lifecycle, critic and archive gate like any gate", but `packages/changes/src/lifecycle.ts` `checkFindings()` is only given `phaseGates(ctx, phase)` (gates.yaml). Blocking trace findings (stories without tests) don't stop the Build, QA or Go/no-go hand-off; only `ci archive-gate` stops the change, after release. The drift gate is in the same position. Test: `lifecycle.test.ts`.
5. **`manual-git-host`**. `packages/cli/src/change-commands.ts` `gitHostFor()` calls `createAdapters(op.runtime)` without a `ManualContext`, so `gitHost: { type: manual }` (ADR 0032, "Plan to Release runs all-manual") throws "a manual adapter writes steps into the metarepo …", uncaught because it is called before the `try`. Same call in `run-commands.ts` `specHandUp()` and `packages/taskrun/src/run.ts` (level pr). Through the CLI the change commands can only use the mock Git host, which lives in one process; the suite shares one mock instance across CLI calls (see the note in `lifecycle.test.ts`). Test: `lifecycle.test.ts`.
6. **`change-folder-layout`**. `packages/changes/src/store.ts` `changeFolder()` joins the fixed `CHANGES_DIR` (`openspec/changes`) to the root and never reads `layoutOf()` (`packages/core/src/metarepo.ts`), whose `openspec` is `.atticus/openspec` for an adopted repo without OpenSpec. `atticus change new` in an adopted Spec Kit repo writes `openspec/changes/<id>/` at the repo root (ADR 0038 promises every command resolves through the layout; ADR 0039 lists it as not yet done). Unadopt still removes these files. Test: `adopt-absorb.test.ts`.
7. **`init-path`** (minor). `packages/cli/src/main.ts`, the `init` branch, passes the raw positional as the org pack name (`name: command`), so `atticus init /some/path/shop-meta --platform shop` is refused ("can't be an org pack name"); only a bare folder name in the current directory works. Use the folder's base name. The suite creates metarepos through `initCommand()`. Test: `adopt-absorb.test.ts`.
8. **`trace-noise`** (minor). `packages/testgen/src/trace.ts` (the task-diff loop that pushes `no diff for task …`) runs `git diff change/<id>...task/<id>/<task>` for every task in tasks.md and prints Git's raw error for each task branch that doesn't exist yet (eight lines on this change). Skip tasks with no task branch or run record. Test: `lifecycle.test.ts`.

Not gaps, but worth knowing:

- The Forge org pack has no `define` gate (`gates.yaml` has design, plan, build, release), so `atticus critic --gate define` answers "There is no gate define" and the Define hand-off needs only the product owner.
- The story bar counts the 11 catalog gaps as covered only after a plan-gate critic round; before it, `plan bar --eval` reports 2 of 13.
- On the fixed design (risk-engine hop removed), `plan bar --eval` with the fixture's eval set reports "stories.md doesn't say why POST /risk/assess … isn't planned": the eval set was written for the seeded design. The lifecycle therefore measures the bar without `--eval`; the eval-set measurement is in `story-bar.test.ts` on the seeded design, as the eval set intends.
- The change is created with the fixture's title "Add a daily transfer limit" (not "Daily transfer limit") so the replayed prompts match the recordings.
