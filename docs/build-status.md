### A. Fix before pushing (main has unpushed local commits)

- [x] **A1. CLI test hang under full load.** `packages/cli/test/learn-cli.test.ts` "defences scan" hung for 89 minutes in a full parallel `pnpm test`; two sandbox tests in the same file exited 1. It passes alone. Fixed: the sandbox ran git synchronously, so a git step stuck under load blocked the process and no test timeout could fire. Git is now asynchronous with a 120 s limit per step, runs no hooks and never prompts; the two sandbox tests have the file's 180 s limit. Passes with the scanner suite running alongside.
- [x] **A2. Performance budgets (m5-exit).** Under full load `/api/setup` took 6.06 s (budget 6 s) and CLI start 3.1 s (budget 2 s). Measure on a quiet machine; check whether the tree-sitter baseline-only flag (ADR 0067) costs start time. Fixed: CLI start was 2.1 s even on a quiet machine because main.ts loaded all 33 command modules and the task runner at start; they now load when their command runs (0.83 s). Quiet-machine numbers on 120 repos: `/api/setup` 4.2 s (budget 6 s), scan 18 s, catalog calls under 0.16 s. `/api/setup` has the least headroom: it reads the whole catalog each call.
- [x] **A3. A pipeline record changes on every rescan.** `QualityAsset/<repo>.pipeline.ci` reports `(details)` changed on each scan with identical files (seen on a real repo). Find the unstable field (likely from the pipeline-model pass, ADR 0062) and make it deterministic.
