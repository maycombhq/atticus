# 0037. Planning, the story bar, manual steps, templates from knowledge and executors (as built)

- Status: accepted
- Date: 2026-10-18

## Decision

**Planning.** `@maycombhq/planner` plans from an approved design: one story per spec requirement, then one per new or changed hop that no requirement covers, then one per uncovered data change. A hop to a system the catalog doesn't know is not planned; the plan says why and the critic raises it. Repos, test kinds, dependencies (a story depends on another when it reads a column the other adds) and open questions are decided deterministically; the org pack's story writer (replayed in tests) writes only the prose, and output for unknown story ids is discarded. `snowDraft` uses the critic's trigger semantics and leaves values the catalog can't give empty and listed, never guessed. **Story bar**: definition of ready is the C6 `definitionOfReady` items mapped to deterministic checks; "invented" means a system, repo, record, interface or operation in neither the catalog nor the design; gaps come from the eval file or, without one, from open questions and knowledge-gap findings. On `fixtures/forge-change`: 5 of 5 stories ready, 13 of 13 seeded gaps covered, nothing invented. Work-item sync and request submission keep external ids in the change's `sync.yaml`, show a dry run first and need one approval per write.

**Manual adapters (ADR 0032 as built).** Each manual adapter implements the C4 interface, so the lifecycle and planner can't tell it from a live one. A write becomes a `ManualStep` (new C4 contract file `executors.ts`, version 1) with every field ready to copy, an export (text, CSV, or the system's import format), an idempotency key, and result fields checked by format when recorded; provisional ids (`manual:<step>`) let children reference parents until the real id is recorded. The Git host opens a PR as a step plus a "report reviews and checks" step; approvals and separation of duties are evaluated on what is recorded. With a manual context, `createAdapters` falls back to manual when a live adapter is unavailable or unauthorized, and records why. The forge change runs from Plan to Release with every external system manual.

**Templates from knowledge (ADR 0032 point 5 as built).** `draftTemplates` reads how-to pages, uploaded documents and request and work-item exports. Deterministic parts: the page's field list and approver, fields filled in every past request (`from: "${record}"` when all values are catalog components), the group that always approved, the stated lead time corroborated by the median working days of past requests, and triggers from the catalog route of past requests' calls; AI writes only summaries and procedure instructions. Every value cites its file and line or tickets. Output is a proposal under `proposals/templates/`, never the org pack; disagreement with an existing template is a triage item. Forge's wiki page and closed-request export reproduce `firewall-rule.yaml` field for field.

**Executors (ADR 0033 as built).** Procedures are C6 data (`process/procedures/*.yaml`, additive). The executor protocol (C4 v1) has ping, run (procedure, step, inputs, change, manual step, idempotency key, submit or fill-only, approval carrying the inputs' sha-256), progress, result (done, failed, needs-person; outputs; evidence) and an idempotency check, over `http` at 127.0.0.1, `command` (JSON lines) or `mcp` (stdio JSON-RPC). People declare executors in `.atticus/executors.yaml` (git-ignored); the org pack allows them per procedure. Not configurable: one approval per write run naming the exact inputs; fill-only only where declared; no secret-looking keys in inputs or outputs and a credential-free environment for programs Atticus starts; failure, timeout or an unreachable executor leaves the manual step open; no retry without a newer approval unless the executor confirms the key unused. Outputs are validated against the step's schema and recorded as the approver's, via the executor. A reference executor speaks all three transports in tests.

## Consequences

Atticus plans, files and tracks every outside step with or without integrations, and teams can automate steps with their own tools under Atticus's approvals. Candidate additive contract changes: a C5 output kind for org-pack proposals, a C6 schema for work-item templates and the documented `from` variables, a `template-drift` triage kind, and C4 `GitHost.closePullRequest`. Not yet: an AI rubric pass in the story bar (the critic's story lens covers judgement), resuming `templates draft` after hand-off mode, push notifications from http executors.
