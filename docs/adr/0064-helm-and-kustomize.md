# 0064. Helm charts and Kustomize overlays, read without running either tool

- Status: accepted (pending review)
- Date: 2026-10-20

## Context

Most Kubernetes estates don't keep plain manifests: they keep a Helm chart with a values file per environment, or a Kustomize base with an overlay per environment. Until now the manifest reader skipped Helm templates ("they need rendering") and read Kustomize files one by one, so a base Deployment came out once, under no environment, and an overlay's patch came out as a half-object. Running `helm template` or `kustomize build` during a scan is not an option: scans are deterministic and read files only (CLAUDE.md rule 4), the binaries aren't part of the bundle, and both can reach the network (chart repositories, remote bases). ADR 0060 also asks that configs be read through parsers, not text patterns.

## Decision

**The manifest reader builds charts and overlays itself, deterministically**, when a reader asks for it (`loadManifests(..., { rendered: true })`). The openshift (0.3.0) and ingress (0.2.0) extractors ask; the other manifest readers (batch, access, mesh, serverless, ML, data pipelines, GCP) read plain files as before. Built objects go to the same object readers as plain ones and carry the environment they were built for, the values or kustomization files behind them, and a group (one Helm release in one environment, or one overlay) so a Service, an HPA or a NetworkPolicy only applies to workloads of its own build.

**Helm.** A folder with `Chart.yaml` that isn't another chart's `charts/<name>` is a chart. Its environments are its values files: `values-<env>.yaml`, `values.<env>.yaml`, `values_<env>.yaml`, `values/<env>.yaml`, `environments|envs|env/<env>.yaml` and `environments|envs|env/<env>/values.yaml`. For each, values are layered as Helm does (`values.yaml`, then the environment's file; maps merge, lists are replaced, `null` removes a key). A chart with no environment file is rendered once with `values.yaml`, under the environment the path or namespace gives (as for plain manifests). With environment files, `values.yaml` alone isn't rendered as an environment of its own. Subcharts are local folders (`charts/<name>`, or `repository: file://...`), with `alias`, `condition` and `tags`, their own `values.yaml` under the parent's section, and the parent's `global`. A dependency that isn't in the repo (a chart repository, a `.tgz`) is reported, never fetched. `requirements.yaml` is read for v1 charts.

Templates are Go `text/template`. A tokenizer splits literal text from `{{ }}` actions (with `{{-`/`-}}` trimming and comments), a parser builds the action tree, and an evaluator runs it over the values. It knows: fields (`.Values.x.y`, `.Chart.Name|Version|AppVersion`, `.Release.Name`, `.Release.Service`, `.Template.Name|BasePath`), variables (`$x :=`, `$`), pipelines and parentheses, `if`/`else if`/`else`, `with`, `range` over lists, maps (sorted keys) and integers, `define`/`include`/`template`, and these functions: `default`, `quote`, `squote`, `upper`, `lower`, `trim`, `trunc`, `trimSuffix`, `trimPrefix`, `replace`, `contains`, `hasPrefix`, `hasSuffix`, `printf` (`%s %v %d %q`), `print`, `toString`, `toYaml`, `nindent`, `indent`, `not`, `and`, `or`, `eq`, `ne`, `empty`, `hasKey`, `required`, `list`, `dict`, `ternary`, `coalesce`, `int`, `len`, `index`. That covers the `helm create` helpers (name, fullname, chart, labels, selectorLabels) and the usual Deployment, Service, Ingress and HPA templates.

**Anything else is unknown, never guessed.** `.Release.Namespace`, `.Release.IsInstall`/`IsUpgrade`/`Revision`, `.Capabilities`, `.Files`, `tpl`, `lookup`, `sha256sum`, random and time functions, any other function, a method call on a value, a field of a missing map (Helm fails there), a number Helm would print in exponent form, and a map or list printed as text are unknown. An unknown value prints as a marker; after the YAML is parsed every scalar or key holding it is dropped, so the field is absent rather than wrong. A condition or a `range` that depends on an unknown value, and syntax the parser doesn't know (`break`, `continue`, `(x).field`), make that template unreadable: it is reported with its line and gives no objects, since which objects it gives depends on it. An object whose name is unknown is reported and left out.

**The release is named after the chart.** `helm install <name>` sets `.Release.Name` at install time; nothing in a chart says it. Atticus uses the chart's name, which is how `helm create`'s fullname helper collapses to the chart name. Components come from the `app` and `app.kubernetes.io/name` labels first (as for plain manifests), so a different release name changes object names, not components.

**Kustomize.** Every `kustomization.yaml` (or `.yml`, `Kustomization`) that no other kustomization uses as a resource, base or component is built: resources and bases (files, and folders with their own kustomization, built first), components (applied to what has been accumulated), `configMapGenerator` literals (with `behavior: merge|replace`), `patchesStrategicMerge`, `patches` (strategic merge or JSON 6902, with `target` by kind, name, namespace, group, version and label selector) and `patchesJson6902`, `namespace`, `namePrefix`/`nameSuffix`, `commonLabels` and `labels` (with `includeSelectors`/`includeTemplates`), `commonAnnotations`, `replicas` and `images` (`newName`, `newTag`, `digest`), in kustomize's order. After a build, references to renamed objects are updated as kustomize does (ConfigMap and Secret references in pod specs, Ingress and Route backends, HPA targets). Strategic merge knows the merge keys of the core workload and Service lists (containers, env, volumes, volumeMounts, ports, imagePullSecrets, ...) and `$patch: delete|replace`; other lists are replaced. JSON 6902 supports add, remove, replace, copy, move and test. The environment is the overlay's (`overlays/prod`, or the overlay's namespace). Files a kustomization uses are not read again as plain manifests.

Not read, and reported: remote bases and components (URLs, `github.com/...`, `?ref=`), `configMapGenerator` `envs` and `files`, and any field the reader doesn't know (`replacements`, `vars`, `helmCharts`, `transformers`, `generators`, ...), with "the objects may differ from what kustomize builds". `secretGenerator` is ignored: Atticus never reads secret values. Generated ConfigMaps keep their name without kustomize's content hash.

**Records.** Deployments, Ingress hosts, HPAs and NetworkPolicies come out per environment through the existing readers. A workload built from a chart or overlay also gives `Setting` records (no contract change): `image` (or `image.<container>`) and `env.<NAME>` (or `env.<container>.<NAME>`) per environment. A value from a ConfigMap built in the same release or overlay is filled in; a Secret stays a reference (`secret:<name>/<key>`), a field ref is `field:<path>`. Evidence keeps the template or resource file and line, then the values files a template read (each at the first line it read that supplied a value), or the kustomization entries and patch files that brought the object in or changed it.

## Consequences

- Chart and overlay repos, the commonest Kubernetes layout, give per-environment Deployments, routes, autoscaling, policies, images and environment variables, offline, with no binary to install.
- What a template reader can't evaluate stays visible: the field is missing and the scan's warnings say which template, line and reason. A person can see what a scan didn't read rather than trusting a guess.
- Plain-manifest behaviour is unchanged for readers that don't ask for builds, and for repos with no `Chart.yaml` or kustomization. In repos with kustomizations, a base's objects now come out once per overlay instead of once under no environment, and overlay patch files are no longer read as objects of their own.
- The infra extractor still reads the first document of YAML files under `k8s/`, `kubernetes/` and `manifests/` as it did; a base kept there also comes out from it, under its namespace or `default`.
- Not yet: helmfile and Argo CD `Application` release names and value overrides, `--set` overrides in pipelines, kustomize `helmCharts`, `replacements` and `vars`, and image and env Settings for plain manifests.
