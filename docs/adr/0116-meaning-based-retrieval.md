# 0116. Retrieval by meaning in the context engine (C5, C6)

- Status: accepted (pending review by the product owner; the model file pending the bank's approval)
- Date: 2026-10-23
- Builds on: ADR 0107 (the context engine), 0117 (judgments by the model, checked by facts), 0074 (the AI reads; every fact cites its code), 0103 (AI steps that hold with Copilot), 0112 (every prompt fits its model), 0002 (stack), 0052 (offline bundle and licences)
- Amends: ADR 0107 points 2 and 3, ADR 0002

## Context

The context engine (ADR 0107) matched words, not meaning. Search was SQLite FTS5 with Porter stemming and BM25: a camelCase name was one token (`renamedAt` is `renamedat`), there were no synonyms, and the model's `search` tool searched the same way. A live run missed a column because the brief said "the renamed timestamp" and the field is `renamedAt`. Wiki sections were indexed whole (a sentence deep in a long one got lost), ingested documents in `inputs/` weren't indexed at all, and the gaps (names the input uses that the index doesn't know) were found with word lists: small words, days, verbs, Given/When/Then words, Title Case lines.

The product owner asked for search by meaning, and for agentic judgment rather than regexes: "everything model-driven, plus a small embedding model shipped inside Atticus and run on the user's machine, turned on only where the eval shows a gain". The research is in the session's design report; its measurements: fp32 vectors are bit-identical run to run, batch 1 against 16 and 1 against 4 threads, and within 1.5e-7 between onnxruntime-node and its WASM build; int8 (q8) models are not (they change with the batch's shape and the backend); brute-force cosine over int8 vectors in JS beats sqlite-vec (77 ms against 185 ms at 50,000 nodes); onnxruntime-node is 28 MB on Windows without DirectML, whose licence is outside ADR 0052's allow-list.

## Decision

### 0. A harder eval first

`packages/evals` (`context-bench.ts`, `runRetrievalBench`) gains 61 retrieval cases (`fixtures/retrieval/cases.yaml`), run straight through `selectContext` on two roots: the Forge scan with 208 look-alike records of eight other invented systems, three glossary terms and their curated aliases, a long wiki page and a Word runbook in `inputs/`; and the shop. Groups: identifier words, paraphrase ("spending cap" for the daily limit, "card issuer" for Northwind Pay), glossary synonyms, multi-hop (two links from anything named), distractors, document-only facts, a sentence deep in a long wiki section, exact names, and inputs nothing answers. Metrics: recall, precision, MRR and tokens at a normal (3,000) and a tight (600) budget. `pnpm --filter @maycombhq/evals eval:context` writes both halves of `docs/evidence/context-eval.md`; the test fails when it is stale. A mode becomes a default only where recall holds on every case and budget (ADR 0107 point 6).

### 1. Without a model (amends ADR 0107 points 2 and 3)

- **Identifier words.** `identifierWords` (core) splits camelCase, PascalCase, acronyms, snake, kebab, dots and versions. The FTS table gains a `words` column (the split forms of a node's names, ids and text, weight 6) and a query's identifiers give their words too. Index version 3: an older index is rebuilt once.
- **Synonyms.** A glossary term or alias the input uses (curated, the org pack's, an item's) brings its other names and the words of the columns it defines as one more ranking. A GlossaryTerm is known by its term and links to the columns its `fields` list (`defines`, `field:fields`); a curated alias decision with a list of names gives each. A synonym never makes a `names` link, resolves a name or closes a gap.
- **Wiki sections in context, in parts.** A section's name is its heading path (page title › parent › heading) and its detail starts with where it was read; a section over about 400 tokens is cut at paragraphs into parts (`id#2`, ...), each with the line it starts on, so a citation stays exact.
- **Documents.** Files in `inputs/` the document ingestor reads (Word, PowerPoint, Excel, PDF, Markdown, HTML, text) become `DocumentSection` nodes (group `document`), one a section, cut like wiki sections, cited by file and section, page or line. Each is screened first with the ingested-content defences; one that hides instructions is kept out and listed as a problem. A document scores 0.8 of a record with the same words: a document never overrides a fact verified from code (rule 6).
- **Rank fusion.** The searches (the input, its title, what it names, the synonyms, and below the model's terms and similarity) are fused by reciprocal rank (k = 1, chosen on the cases from 0 to 60), each keeping only hits with at least 0.3 of its best BM25. Every seed says which rankings found it and at what rank. `kindWeights`, which no step set, is removed.

### 2. A local embedding model (C5, C6; amends ADR 0002)

- **C5: the `Embedder` interface** (`@maycombhq/ai`): `{ id, dim, maxTokens, floor?, backend, embed(texts, "query" | "document") → { q: Int8Array, scale }[] }`. Vectors are unit vectors as int8 with one scale; scoring is an exact integer dot product, ties by key, so the same stored vectors rank the same on every machine. `HashEmbedder` (feature hashing of words and their three-letter pieces) is the tests' embedder; `RecordedEmbedder` replays vectors a real model gave, as the replay runtime replays answers.
- **`@maycombhq/embed`:** `OnnxEmbedder` runs an fp32 ONNX model with onnxruntime-node on the CPU (one text a run, one thread), falling back to onnxruntime-web's WASM build where the native one won't load; an in-house BERT WordPiece tokenizer (golden token ids against each model's own tokenizer, 20 texts, exact); a model folder with `atticus-model.yaml` (name, `dtype: fp32` only, file, sha256, dimension, token limit, pooling, query prefix, similarity floor, licence, source). The model's sha256 is checked before it loads. onnxruntime is not a dependency in the lockfile: the offline bundle carries it.
- **Vectors** live in `.index/vectors.sqlite` (attached to the index), keyed by the model's id and the text's sha256, never by file: an unchanged text isn't embedded again, a moved file costs nothing, a rebuild of the index keeps them. Query vectors are kept the same way. A node is embedded as its kind, its name and id as words, and its text (a document's path is left out).
- **Similar in meaning** is one more ranking in the fusion, labelled `similar in meaning #n (cos 0.62)`, only while every node has a vector; until then it is off and the selection says so (`3,120 of 50,000 embedded by <model> (atticus index embed)`). An open index embeds up to 500 missing texts (a search by meaning from the command line, all of them); `atticus index embed` does the rest. The selection's version and cache key carry the model's id. Similarity never creates a stored link, resolves a name, closes a gap or becomes a fact.
- **Tools (C5):** `search` takes `by: words | meaning | both` (default both; words only without a model); a new read-only `similar { id, kinds?, limit? }` lists what reads like an id, said to be a hint, not a link. Both are in the MCP server and as `atticus query --search --by`, `atticus context similar`.
- **C6:** `runtime.yaml` gains an optional `retrieval` section: `embeddings.model` (`off`, the default; `bundled`, the `@maycombhq/embed-model` package the bundle carries; or a model folder), `embeddings.runtime` (a folder whose `node_modules` holds onnxruntime), `expansion` and `rerank` (both false). Additive and optional, so no schema version bump, as `history` and `buildEngine` before it: a pack without it reads as everything off.
- **The model:** `all-MiniLM-L6-v2` (fp32, 87 MB, Apache-2.0, mean pooling, 256 tokens, floor 0.25) by the eval; `snowflake-arctic-embed-xs` (fp32, 87 MB, Apache-2.0, CLS pooling, query prefix, floor 0.7) is measured beside it in the evidence page and is a one-line switch. Training data, which the bank's legal team must sign off: MiniLM's card lists its fine-tuning sets (over a billion pairs, among them MS MARCO, whose terms are research-only, Reddit, Stack Exchange, S2ORC and others); arctic-embed's card says only "a mix of public datasets and proprietary web search data" and that "the released models can be used for commercial purposes free of charge", its paper names PAQ, Stack Exchange, S2ORC, HotpotQA, NQ and Fever, and its card says it is based on all-MiniLM-L6-v2 (the paper gives MiniLM-L6-H384-uncased).
- **The bundle** (replaced by the last addendum, where the model and runtime are npm packages): `pnpm bundle` with `ATTICUS_BUNDLE_MODEL` (a model folder with its LICENSE) and `ATTICUS_BUNDLE_ORT` adds the model as `node_modules/@maycombhq/embed-model` (checked against its manifest's sha256, fp32 only), onnxruntime-node's CPU build for the one platform (DirectML, dxcompiler and dxil left out), onnxruntime-common and onnxruntime-web's WASM files; the SBOM lists the model as a CycloneDX `machine-learning-model` with its hash; `pnpm licences` and the bundle fail on a DirectML file anywhere; `bundle:test` turns the model on in its sandbox, runs `atticus index embed` and a search by meaning with the network pointed nowhere; `atticus doctor` reports the model, its size, licence and runtime. sqlite-vec is rejected: pre-1.0, a native extension to load at a bank, and slower here. transformers.js is rejected: it brings a downloader, sharp and 141 MB of WASM builds.

### 3. The model's expansion of the input (C5)

`packages/planner/src/stages/expand.ts`, called through `retrieve` in `engine.ts` before a step's selection (change needs, feature, architecture, stories): one small call (6,000 tokens) with the step's input and the estate's names and aliases (systems, components, stores, tables, glossary terms, flows, items; one source a kind, so the pack fits the model) asking for search terms in the estate's words and every proper name the input uses, each mapped to an id or said new, with the input's words it took it from. Atticus checks it: a name whose words aren't in the input is dropped, an id the index doesn't have is dropped (the name stays a gap), and each drop is recorded. The terms become rankings, the ids seeds (0.9, below an exact name), and the names the index doesn't know become the gaps: **the word lists are gone** (`NOT_NAME`, `VERBS`, `STEP_WORDS`, Title Case); `knownName` only checks that the index lacks a name. Without the expansion, only names the input marks by their form (an endpoint, a name in backticks) are asked about.

The answer is kept in the judgments store of ADR 0117 (`judgments/expansion/<key>.yaml`, the key a hash of the input, the index's version and the runtime; answered by the run it names, its quotes the input's words, and a person can override it); the same commit and input give the same answer with no call. In hand-off mode the expansion is **a hand-off of its own, one prompt per round**: the step returns waiting on the `context-expander` run; the runner answers it and resumes the step with that run, which reads it in and hands off its own prompt. With no model or with it off, the engine falls back to point 1 and 2.

**The run record, version 3** (C5): `retrieval` holds the expansion (its run, whether it was a kept answer, terms, names with their quotes, drops), the rerank, and whether similarity ranked. `migrateRunSummary` reads versions 1 and 2 as 3 with none. `atticus runs show`, the transcript (`GET /api/runs/{runId}/transcript`, `retrieval`; API 2.15.0) and the app's Model runs screen show it as text.

### 4. The model's rerank of the candidates (C5)

`stages/rerank.ts`: only when what the engine found doesn't fit the room, one call shows the top 40 candidates, one line each, with the input, and asks for them in the order the step needs them, leaving out what it doesn't. The answer must name only candidates it was shown, each once, else it is ignored and the engine's order stands (recorded `used: false`). `selectContext` takes the order (`SelectOptions.order`); the fit runs in it; a candidate it dropped is left out with "the model judged it not needed". Scores, links and gaps are the engine's. Kept and handed off like the expansion.

## Consequences

- The miss that started this is found by the words alone (from rank 27 to rank 2), and a brief's paraphrases by meaning where the model is installed.
- Gaps from plain prose now need the expansion, which is off by default: with it off, a vendor named only in a sentence (not in backticks) is no longer asked about. That is the price of taking the word lists out; turning the expansion on brings the names back, judged by the model and checked by the index.
- Expansion and rerank cost one or two model calls a step (two extra hand-off rounds in hand-off mode), each kept and reused for the same input and index.
- Embeddings need the model file (87 MB) and onnxruntime (28 MB on Windows); a first build of a big estate takes minutes to an hour on a low-end laptop.
- Not built or not measured: real Copilot recordings for the expansion and the rerank (the eval's expansion answers are stand-ins); the step bench's rows with expansion, rerank or embeddings (only the retrieval cases have them); cross-CPU bit-identity of the vectors beyond this machine (the opt-in check, `ATTICUS_EMBED_MODEL`, runs where a model is); a multilingual model; suggestions of links by meaning for a person to confirm.

## Addendum (2026-10-24): the defaults changed, by the product owner's decision

The product owner read the eval and decided: "use the best model" and "turn rewording on". The defaults above (embeddings off until configured, the expansion off) change; the measurements don't.

1. **Embeddings on, with the best-scoring model.** `retrieval.embeddings.model` defaults to `bundled`, the `@maycombhq/embed-model` package (all-MiniLM-L6-v2): 0.96 recall on all answered retrieval cases at the normal budget, against 0.81 for the lexical engine and 0.84 for snowflake-arctic-embed-xs. Where the model or onnxruntime isn't installed (a dev checkout, or a bank that hasn't approved them), the engine falls back to point 1: `openIndex` never fails on the model (`embedderFor` catches a model it can't open, the index catches one that can't run), the selection says why similarity is off, and `atticus doctor` reports it under "Embedding model": a note for the default, a warning when `runtime.yaml` names a model that can't be used. Nothing is ever downloaded. `model: off` still turns it off. The legal sign-off on the training data (point 2) is unchanged and still owed.
2. **The expansion on.** `retrieval.expansion` defaults to true, though the eval's expansion answers are hand-written stand-ins: the decision is the product owner's, and recording real answers at the GPT-4o mini floor is the measurement still owed (build status G8). With it on, a vendor or system named only in prose is a gap again (fixture: `packages/planner/test/fixtures/prose-vendor`). The rerank stays off: not measured.
3. **One reader of the settings (C6).** `RetrievalSettings` and `retrievalOf(runtime)` in `@maycombhq/core` fill the defaults, so a pack without the section, one with `retrieval: {}` and one that sets a single switch agree on the rest. The embed resolver, the planner's needs step, the stage loop and the engine read through it. Still additive and optional: no schema version bump.
4. **Hand-off mode stays usable.** The expansion is one extra round per step that uses the engine, first: a feature stage hands off the expansion, then its drafts and lenses as before (the stage loop's hand-off test counts rounds: expander, placer, placer). Its prompt is the step's input and the estate's names within 6,000 tokens (about 5.5 KB on the M3 fixture's change). The kept answer's key is now the input, a hash of the names the model was shown and the runtime (`v: 2`), not the index's generation: before, a stage's own draft changed the generation and the expansion was asked again on the next round. A step run again without `--resume` waits on the same expansion prompt, or reads its answer in, through a pending marker beside the index (`.index/pending-judgments/`, disposable). An answer that fails its check is left out with a note in the step's context report, and the step goes on lexically. A whole change in hand-off mode gains four rounds (needs, feature, architecture, stories), each once per input.
5. **The step bench** pins the model and the expansion off in its roots, so its rows measure the engine itself on every machine; the retrieval cases measure the modes.

## Addendum: the model comes with Atticus (2026-10-24, after the one above)

The product owner decided that the model ships with Atticus and is on by default: a developer installs Atticus with npm from the organisation's mirror (or from the offline bundle), installs the editor extension and starts a metarepo, and search by meaning works, with nothing else to run.

- **`@maycombhq/embed-model`** is an npm package: all-MiniLM-L6-v2 as fp32 ONNX (87 MB), its tokenizer, the model card, the Apache License 2.0 and `atticus-model.yaml`. `@maycombhq/embed` depends on it, so `npm install @maycombhq/cli` installs it, and the default the addendum above set, `retrieval.embeddings.model: bundled`, is there after an install. The fallback it describes stays: where the files are missing (a checkout before `pnpm model:fetch`), the engine searches by words and names and `atticus doctor` says why.
- **The runtime** is onnxruntime 1.30.0, repackaged rather than depended on. onnxruntime-node's install script downloads CUDA binaries from NuGet on linux-x64 unless told to skip, which a bank's mirror and proxy block, and its package carries DirectML on Windows, whose licence isn't on the allowed list. So Atticus publishes `@maycombhq/onnxruntime-<platform>-<arch>` (win32-x64, win32-arm64, linux-x64, linux-arm64, darwin-arm64): onnxruntime-node's own `dist/` and its CPU build for that platform, byte for byte, with no install script and no DirectML. Each package declares its `os` and `cpu`, and `@maycombhq/embed` takes them as optional dependencies, so npm installs only the one for the machine. `@maycombhq/onnxruntime-wasm` carries the three files of onnxruntime-web's WASM build the fallback uses (14 MB, against 141 MB for the whole package). They depend on `onnxruntime-common@1.30.0` (no install script). The embedder looks for these packages first, then onnxruntime-node and onnxruntime-web.
- **Pinned and checked.** None of these files is in git. Each package's `pins.json` names its sources at exact revisions and the sha256 of each source and of each file it publishes: the model and tokenizer from Xenova/all-MiniLM-L6-v2 at revision 751bff37182d3f1213fa05d7196b954e230abad9 on Hugging Face, the licence text from apache.org, onnxruntime-node and onnxruntime-web 1.30.0 from the npm registry, and onnxruntime's MIT licence from its repository at v1.30.0. `prepack` (publishing), `pnpm model:fetch` (a checkout) and `pnpm bundle` fill a package from its pins through a cache by sha256 (`.cache/pinned`, gitignored; CI caches it), refusing any byte that differs. That is the only network use, and only when a package is built: never at run time, in an install, a scan or a test. `pnpm model:pins` writes the pins again for a new version, for review.
- **Tests** run with `ATTICUS_EMBEDDINGS=off` (vitest.shared.mjs), so no test loads the model unless it passes one; the tests that need the real model run where its files are (after `pnpm model:fetch`) and are skipped in CI.
- **The offline bundle** carries the same packages for the platform it is built on (about 113 MB on Windows); the environment variables that pointed it at a model and a runtime are gone. `bundle:test` checks the model is inside and searches by meaning with the network pointed nowhere.
- **The editors** run the installed `atticus` (the `atticus.path` setting, or PATH), so they don't carry the model.
- **What the mirror must allow:** the `@maycombhq/*` packages (among them `@maycombhq/embed-model` and the runtime packages for each platform its people use) and `onnxruntime-common@1.30.0`. An npm install of Atticus grows by about 130 MB on Windows (the model 87 MB, the runtime 28 MB, the WASM fallback 14 MB); a CI install of the repository by `onnxruntime-common` alone (66 KB), since the workspace packages hold no files until fetched.
- An open index embeds up to 500 missing texts, and a search by meaning from the command line all of them, so a new metarepo searches by meaning at once.

## Addendum (2026-10-24): a name the code has is not a gap

A live architecture run listed "names the change uses that nothing Atticus has read says anything about": seven classes of the repo the change touches (a controller, a service, entities). They came from the expansion (point 3). The architecture step's input holds today's flows, and their steps name the code ("OrderController.place receives the new order"). The expansion lists every proper name the input uses. `knownName` checked them against the index only, and the catalog has no record for a class: classes aren't architecture facts, and a catalog record of each would be noise. The entities' tables are in the catalog under their table names. Whether `ChatMessage` is the `chat_message` table is meaning, the model's to read; it isn't for a name rule to decide. So the catalog was right not to have them. The step was wrong to call them gaps.

- **Searching the code is a fact check.** Before a name becomes a gap, `gapContext` searches every repo cloned in the workspace for it (`namesInCode` in `@maycombhq/index`, ADR 0118's walk: `.gitignore` and `.git` skipped, no binaries, the same caps). A name found as a whole word on any line (no letter, digit or underscore just before or after it) is in the code. It is not a gap. The step's context reports it with the first line that names it (`inCode`), the model gets those lines as data (`names-in-code`) to read with `show_code` or `grep`, and `contextLines` prints them.
- **A gap says it searched.** Only a name found in neither the index nor the code is a gap. The gap block and the command line name the repos searched (`searched`), or say that no repo is cloned, so no code was searched.
- Nothing found in the code becomes a fact or a link. It only keeps a name from being asked about.
